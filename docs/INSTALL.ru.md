# Установка и обновления

[English](INSTALL.md) · **Русский** · [К описанию проекта](../README.ru.md)

## Установка

Установщик ставит пакеты, раскатывает конфиги и настраивает вход в систему. Делает это
**обратимо**, сохраняя всё, что уже есть на машине.

```bash
# 1. Склонировать репозиторий (на голой системе ещё нет git:
#    sudo pacman -S git  /  sudo apt install git)
git clone https://github.com/valentinesowl/hyprwe.git ~/hwe
cd ~/hwe

# 2. Выйти в TTY (Ctrl+Alt+F2) и раскатать hyprwe на эту машину.
#    Из графической сессии установщик откажется стартовать: он трогает композитор,
#    бар и login-shell — это не делается из-под работающего Hyprland.
./bin/hwe install
```

Что делает `hwe install`:

- ставит `pkg/core.lst` + `pkg/dev.lst` из репозиториев дистрибутива (на Ubuntu имена
  проходят через `pkg/map/apt.map`); на Arch бутстрапится `paru`, если `pkg/aur.lst`
  непустой — на Ubuntu AUR-пакеты пропускаются с уведомлением;
- симлинкует `config/*` в `~/.config`, **сохраняя** прежние конфиги рядом как `*.hwe-bak`;
- генерирует и применяет тему по умолчанию (`mocha`);
- делает `zsh` login-шеллом и включает NetworkManager + SDDM.

После установки `hwe` линкуется в `/usr/local/bin/hwe` — дальше вызывай просто `hwe …`.
Первый вход подскажет `SUPER + /` — шпаргалку по горячим клавишам.

Конфиги деплоятся **симлинками** на репозиторий: правки `~/hwe/config/...` применяются сразу.
Собственные настройки принадлежат `~/.config/hwe/` — см. [Персонализацию](CUSTOMIZATION.ru.md).

## GPU

Intel/AMD работают из коробки — mesa приезжает вместе с Hyprland, драйверы находятся в ядре.
**NVIDIA** установщик определяет по `lspci` и настраивает сам — только на Arch; на Ubuntu
он сообщает об этом и GPU не трогает. Настройка включает драйвер (open-модули для Turing+,
проприетарный для старых карт), DRM-modeset, модули в initramfs и pacman-хук пересборки.
Поскольку это затрагивает загрузку, установщик спрашивает подтверждение.

**Эта ветка пока не проверена на живом NVIDIA-железе** — разработка шла на Intel.
`HWE_NO_NVIDIA=1` пропускает её целиком; `HWE_NVIDIA_DRIVER=<пакет>` фиксирует драйвер,
если детект поколения ошибся. `hwe uninstall` этот пласт (initramfs/модули) не откатывает.

## Безопасность и opt-out

- **Полное обновление системы на реальной машине — по флагу.** Апгрейд (`pacman -Su` /
  `apt-get upgrade`) идёт с `HWE_FULL_UPGRADE=1` или в unattended VM. Иначе установка
  работает против текущей БД пакетов (на Ubuntu списки всё равно обновляются — apt этого требует).
- **Opt-out:** `HWE_NO_ZSH=1` (оставить shell), `HWE_NO_NM=1` (оставить сеть),
  `HWE_NO_NVIDIA=1` (оставить GPU), `HWE_FORCE=1` (запустить из графической сессии на свой риск).
- **Без вопросов:** `HWE_ASSUME_YES=1` отвечает «да» на подтверждения установки, NVIDIA,
  пакетов и удаления VM. Он намеренно **не** покрывает согласие на PPA (`HWE_HYPR_SOURCE=ppa`).
- **Откат:** `hwe uninstall` возвращает прежние конфиги из `*.hwe-bak` и предлагает вернуть
  login-shell; пакеты и сервисы остаются на месте.
- `NO_COLOR=1` выключает цветной вывод; `HWE_DEFAULT_THEME=<имя>` выбирает начальную тему
  (по умолчанию `mocha`).

## Ubuntu

hyprwe нацелен на **Ubuntu 27.04 в экспериментальном режиме** и требует **Hyprland 0.57.0
или новее** (рекомендуется 0.57.2). **Ubuntu 26.04 не поддерживается hyprwe 2.x**: кандидат
в её архиве — 0.53.3, поэтому установка остановится до изменения пакетов, конфигов, shell
и сервисов. Для Hyprland 0.53–0.56 используй линию hyprwe 1.4.x `legacy-conf`.

**Откуда берётся композитор — твоё решение, и hyprwe не примет его молча.**

| `HWE_HYPR_SOURCE` | Требование | Что выдаёшь |
|---|---|---|
| `repo` *(по умолчанию)* | кандидат Ubuntu должен быть >= 0.57.0 | ничего нового — машина уже доверяет дистрибутиву |
| `ppa` | явно выбранный сторонний кандидат тоже >= 0.57.0 | ключ постороннего, ограниченный apt-пином стеком Hyprland |

```bash
hwe install                        # кандидат Ubuntu, после проверки версии
HWE_HYPR_SOURCE=ppa hwe install    # осознанно взять сторонний репозиторий
```

Наличие подходящей версии в PPA не предполагается: hyprwe проверяет кандидата и отклоняет
слишком старый. Обычное подключение стороннего репозитория даёт его ключу право ставить
*любые* пакеты; hyprwe ограничивает его стеком композитора. Выбор `HWE_HYPR_SOURCE=ppa`
**и есть** согласие, которое не покрывается `HWE_ASSUME_YES`. Сборка из исходников не
предлагается, и ради прохождения проверки hyprwe не меняет источник.

Пакеты Ubuntu могут включать пользовательские systemd-юниты при установке. hyprwe запускает
программы сессии из `config/hypr/autostart.lua`, поэтому дублирующие юниты отключаются.
Остальные различия пакетов записаны в `pkg/map/apt.map`; перед объявлением Ubuntu 27.04
стабильной целью карту нужно заново проверить на этом выпуске.

## Держать машину в согласии с репозиторием

```bash
hwe update            # подтянуть репозиторий и привести машину в соответствие
hwe update --check    # только чтение: показать расхождения, ничего не менять
hwe doctor            # та же проверка (голый doctor = doctor host)
hwe doctor vm         # готовность хоста к VM-воркфлоу
hwe doctor --report   # готовый для issue блок с результатами проверки
```

`hwe update` тянет `--ff-only` и останавливается, если дерево грязное или история разошлась —
молча мержить или прятать работу в stash он не станет. Дальше перелинковывает конфиги,
переприменяет тему и предлагает доустановить недостающие пакеты. `hwe doctor` показывает те
же расхождения, ничего не трогая: симлинки, пакеты, личный слой, login-shell, ошибки Hyprland
и стек screen sharing. Обнаружение и починка используют одни примитивы установки, поэтому
проверка не расходится с тем, что реально раскатывает установщик.
