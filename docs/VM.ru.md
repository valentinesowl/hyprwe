# Репетиция в одноразовой VM

[English](VM.md) · **Русский** · [К описанию проекта](../README.ru.md)

`hwe vm up` поднимает **одноразовую** Arch- или Ubuntu-виртуалку, видимую в virt-manager,
и разворачивает в ней **твою локальную ветку git** прямо из репозитория. Внутри отрабатывает
тот же `hwe install`, что и на железе, так что это честная репетиция установки.

## Команды

```bash
# 0. Проверить хост (libvirtd, группы, сеть, KVM)
./bin/hwe doctor vm

# 1. Поднять VM с текущей веткой (или указать конкретную)
./bin/hwe vm up
./bin/hwe vm up feature-x

# 1b. Или развернуть рабочее дерево как есть, ничего не коммитя
./bin/hwe vm up --uncommitted

# 1c. Ubuntu 27.04 (экспериментально): сначала собрать локальный базовый образ
./bin/build-ubuntu-cloud
HWE_VM_DISTRO=ubuntu ./bin/hwe vm up --uncommitted

# 2. Зайти внутрь (когда cloud-init отработает)
./bin/hwe vm ssh
./bin/hwe vm console      # или смотреть загрузку в virt-manager
./bin/hwe vm status       # состояние + IP

# 3. Пересобрать начисто / снести
./bin/hwe vm rebuild
./bin/hwe vm destroy
```

По умолчанию в VM едет последний коммит ветки. `--uncommitted` разворачивает рабочее дерево —
с изменёнными, застейдженными, удалёнными и новыми файлами, — так что правку можно проверить
до коммита. Снимок собирается через отдельный индекс и временный `--shared` клон: индекс,
рабочее дерево и ветки не двигаются, коммита в истории не появляется. Игнорируемые файлы не
едут — гость соберёт их сам.

Логин в VM: пользователь **`hwe`**, пароль **печатается при `vm up`** и генерируется заново
на каждую сборку. Твои `~/.ssh/id_*.pub` прокидываются в гостя автоматически — обычно вход
по ключу, а пароль остаётся только для консоли. Конфиги в VM деплоятся **симлинками** на
репозиторий, так что правки в `~/hwe/config/...` видны сразу.

## Как это работает

1. Cloud-образ Arch скачивается в `~/.cache/hwe/` и проверяется по закреплённому fingerprint'у
   arch-boxes. Для Ubuntu 27.04 `bin/build-ubuntu-cloud` проверяет подписанный Canonical
   `SHA256SUMS` Ubuntu Base закреплённым CD-image ключом, собирает локальный NoCloud-образ и
   устанавливает его в тот же кэш. Неаутентифицированные входные данные отклоняются.
2. hyprwe делает `git bundle` выбранной ветки — или, с `--uncommitted`, одноразового снимка
   рабочего дерева — и кладёт его на **NoCloud seed ISO** (`xorriso`).
3. `virt-install --import` создаёт **libvirt-домен**, видимый в virt-manager.
4. `cloud-init` создаёт пользователя, монтирует seed, клонирует bundle и запускает
   `hwe install` — машина поднимается сама, от образа до готового desktop. Arch-гость сначала
   полностью обновляет базовый образ и только затем ставит bootstrap-пакеты, избегая
   неподдерживаемого partial upgrade на старом cloud-снимке.

## Переопределения

| Переменная | Дефолт | Назначение |
|---|---|---|
| `HWE_VM_DISTRO` | `arch` | дистрибутив гостя: `arch` или `ubuntu` |
| `HWE_VM_UBUNTU_RELEASE` | `27.04` | экспериментальный релиз Ubuntu |
| `HWE_HYPR_SOURCE` | `repo` | откуда в госте Hyprland: `repo` или `ppa` |
| `HWE_VM_NAME` | по дистрибутиву | имя домена libvirt (`hwe-dev`, `hwe-dev-ubuntu`) |
| `HWE_VM_MEMORY` | `4096` | RAM, МиБ |
| `HWE_VM_VCPUS` | `4` | vCPU |
| `HWE_VM_DISK_SIZE` | `24G` | размер корневого диска |
| `HWE_VM_USER` | `hwe` | имя пользователя в госте |
| `HWE_VM_PASSWORD` | *случайный* | пароль (задать, чтобы зафиксировать) |
| `HWE_LIBVIRT_URI` | `qemu:///system` | URI libvirt (дефолт virt-manager) |
| `HWE_VM_NETWORK` | `default` | имя libvirt-сети |
| `HWE_IMAGE_URL` | по дистрибутиву | базовый образ; неподтверждённый отклоняется |

Ubuntu 27.04 остаётся экспериментальной целью. Пути Arch и Ubuntu проверены end-to-end в
протестированных конфигурациях x86_64 libvirt/QEMU, а не на любой возможной хост-системе.
