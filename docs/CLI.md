## Commands

| Command | What it does |
|---|---|
| `hwe install` | install packages and deploy configs onto **this** machine |
| `hwe update [--check]` | pull the repo and reconcile this machine |
| `hwe uninstall` | revert config symlinks and login shell (packages/services stay) |
| `hwe control` | toggle the live Control Shelf (`SUPER+SHIFT+Up`) |
| `hwe center [themes\|sessions\|system\|vm\|tools]` | keyboard-driven command center (`SUPER+A`) |
| `hwe theme <list\|apply\|pick\|validate\|current\|sddm>` | render every component's colours from a theme |
| `hwe wall <list\|set\|random\|pick\|current\|restore>` | wallpaper — generated by the theme or your own |
| `hwe power` | session menu with Cancel-first power confirmations |
| `hwe keys` | keybinding cheatsheet generated from the binds (`SUPER+/`) |
| `hwe clip <show\|wipe>` | clipboard history (`SUPER+C`) |
| `hwe record <toggle\|region>` | screen recording → `~/Videos` |
| `hwe screenshot <screen\|region\|file\|annotate>` | screenshots with success, cancel and error feedback |
| `hwe sunset <toggle\|on\|off\|status>` | night light |
| `hwe checkconfig [--notify]` | verify the Lua config and running Hyprland errors |
| `hwe vm <up\|ssh\|console\|status\|list\|down\|destroy\|rebuild>` | local VM lifecycle |
| `hwe doctor [host\|vm\|--report]` | health-check this machine or the VM host |
| `hwe session <save\|restore\|list\|clear>` | named desktop snapshots |
| `hwe version` | print the version |

## Control Shelf

Press `SUPER+SHIFT+Up` or run `hwe control` to toggle the bottom shelf. It shows the active
wallpaper and theme, compiler coverage, current window geometry, snapshots with direct
Restore/Delete actions, configuration layers, health and updates together. Doctor and update
output stays in its permanent region. **Escape**, the shortcut or clicking outside closes the
shelf without side effects. The persistent `reduced_motion` personal setting disables its slide
animation. General system controls belong to a separate upper shelf.
Source files open in `$EDITOR` with Nano as the default; directories open in Dolphin.

## Command center

Press `SUPER+A` or run `hwe center`. The main menu groups the workstation's own workflows
into **Themes**, **Sessions**, **System**, **Virtual machines** and **Utilities**. A section
can also be opened directly, for example `hwe center sessions` or `hwe center system`.

The center is a navigation layer, not a second implementation: every action delegates to the
same `hwe` command documented below. **Escape** cancels without side effects. Health and drift
reports open in the menu; long VM and update operations open in Kitty so their progress stays
visible. Snapshot replacement and destructive VM operations require a Cancel-first graphical
confirmation.

Its geometry and typography come from the theme's optional `[ui]` contract. See
[Writing a theme](../themes/README.md).

## Named session snapshots

```bash
hwe session save 1       # save every window and workspace to slot 1
hwe session restore 1    # restore that session
hwe session list         # names, dates and snapshot sizes
hwe session clear 1      # delete one snapshot
hwe session clear --all  # delete all snapshots (with confirmation)
```

A snapshot covers every mapped window, workspace and monitor, including the active workspace
and tiled window geometry. Restore reuses matching open applications, launches missing ones
and applies positions through a Lua layout provider without making windows floating. It does
not close your current windows. Nothing is saved or restored automatically.

Snapshots live in `~/.local/state/hwe/sessions/` and are written atomically with mode `0600`.
Window titles, PIDs and command-line arguments are not persisted. Application-internal state
(browser tabs, terminal processes and unsaved documents) belongs to those applications.

`SUPER+S` enters session mode with a persistent Waybar indicator and visible key instructions.
A save/restore operation exits automatically. Repeated `SUPER+S`, Escape, unrelated input or
clicking the indicator cancels without changing the desktop. `SUPER+SPACE` remains available
for keyboard-layout switching even while the submap is active.

## Themes

A theme is **one** file, `themes/<name>/theme.toml`: a private `[palette]` and the semantic
`[sem]` contract. The templates in `templates/*.j2` read **roles only**, so a new theme comes
down to a single `theme.toml`.

```bash
hwe theme list                # available themes (the current one is marked *)
hwe theme apply mocha         # render + deploy + live reload of every component
hwe theme pick                # rofi gallery with previews (SUPER+SHIFT+T)
hwe theme validate <name>     # check a theme against the contract
```

The picker shows all twelve themes in a quiet 4×3 gallery of graphic identity cards. **Enter**
applies the selected theme, and **Escape** cancels without changing anything. Custom themes
without `preview.png` get a cached generated card, with a text fallback if generation fails.

The separate `[font]` table defines the family and sizes for each surface, with fallback
defaults. `theme apply` renders colours into Hyprland, Waybar, Kitty, Rofi, Mako, GTK 3/4,
Kvantum, Starship, kdeglobals and Hyprlock; then it reloads the running applications and sets
the theme's wallpaper. The SDDM greeter is synced separately with `hwe theme sddm`.

**Themes included:** `amethyst` · `default` · `ember` · `frost` · `garden` · `mocha` ·
`mono` · `neon` · `paper` · `linen` · `rust` · `void`.
To add your own, see [Writing a theme](../themes/README.md).

## Wallpapers

```bash
hwe wall pick                 # rofi with thumbnails (SUPER+SHIFT+W)
hwe wall random [theme]       # a random wallpaper of the theme
hwe wall set <path|name>      # a specific file, or a name from `wall list`
```

Every theme carries a generated `wallpaper.png`. Put your own photos/GIFs into
`~/.config/hwe/themes/<name>/wallpapers/` and they show up next to it; the legacy in-checkout
path is supported too.

`awww` renders both static images and animated GIFs. `mono` includes a seamless six-second
animation. On Ubuntu, where `awww` is not packaged, hyprwe falls back to `hyprpaper` and
static wallpapers. Hyprlock and SDDM always use a separate static image.

## Repository layout

```text
bin/                 hwe CLI and the verified Ubuntu cloud-image builder
lib/                 install, update, theme, session, VM and desktop command implementations
provision/           cloud-init, shared installer, personal-layer skeletons and SDDM
pkg/                 package lists, Ubuntu package map and font lock
themes/<name>/       theme.toml, generated wallpaper and preview card
templates/           Jinja templates rendered from the semantic theme roles
config/              XDG configs symlinked into ~/.config
scripts/             theme, wallpaper, preview and Waybar generators
tests/               pytest and Bats suites
justfile             development tasks
```

## Development commands

```bash
just            # list the tasks
just up         # = hwe vm up
just check      # everything CI checks: linters + tests
just test       # tests only: pytest + bats
just lint       # shellcheck over every script
just fmt        # shfmt (4 spaces; not a gate)
just walls      # regenerate wallpapers
just previews   # regenerate theme previews
just gallery    # rebuild assets/themes.png and assets/social-preview.png
```

The quality gates are installed along with everything else by `hwe install`, and CI installs
exactly the same ones. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the development workflow.
